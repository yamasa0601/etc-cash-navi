# 現金ETCナビ

ETC 専用インターチェンジを避けて、**現金で通れる高速道路の経路**を組み立てる Web アプリ (PWA)。
ETC カードを持たずに高速道路を使う必要がある人向け。

出発地と目的地を入れると、現金で入れる IC と現金で出られる IC を選んで経路を提示し、
実際の運転は Google マップに引き継ぐ。

## なぜ必要か

NEXCO 3 社は料金所の ETC 専用化を進めており、2026 年春時点で NEXCO 西日本だけで
94 か所が ETC 専用になっている。現金車が誤って進入すると、停車して係員対応となり、
その場では支払えず後日請求になる。どの IC が現金で使えるかは各社が別々の形式
(HTML / PDF) で公開しているだけで、地図アプリからは調べられない。

## 仕組み

日本の高速道路は入口で券を取り出口で払うので、現金で走り切れるかは
**入口 IC と出口 IC がそれぞれ現金対応かどうか**で決まる。通過するだけの IC は関係ない。
ただし本線料金所が ETC 専用だと、その区間自体を通り抜けられない。

そのため経路探索はこう組む:

1. 出発地の近くで「現金で入れる」IC を候補に集める
2. 目的地の近くで「現金で出られる」IC を候補に集める
3. 総当たり表で (一般道 + 高速 + 一般道) の合計時間が最小の組を選ぶ
4. 区間ごとに有料道路の可否を分けて経路を確定する

一般道区間と高速区間を分けて計算するのは、まとめて計算すると選んだ IC より手前で
高速に乗ってしまい、ETC 専用 IC を通りかねないため。

## データ

| 内容 | 出典 | 形式 |
| --- | --- | --- |
| ETC 専用料金所 (東) | [ドラぷら](https://www.driveplaza.com/etc/etc_guide/etc_only_station/) | HTML 表 |
| ETC 専用料金所 (中) | [NEXCO 中日本](https://dc2.c-nexco.co.jp/etc/service/dedicated_etc.html) | HTML 表 |
| ETC 専用料金所 (西) | [NEXCO 西日本](https://www.w-nexco.co.jp/etc/etc-only/) | PDF |
| IC・料金所の位置、路線番号 | OpenStreetMap (Overpass API) | JSON |
| 都道府県界 | [dataofjapan/land](https://github.com/dataofjapan/land) | GeoJSON |
| 地図タイル | 国土地理院 | ラスタタイル |
| 経路計算 | OSM 公開 Valhalla サーバー | JSON API |

すべて無料・API キー不要。`data/ic.json` に統合して配信する (約 440 KB)。

### 検討して使わなかったもの

- **OpenStreetMap の支払方法タグ**: 全国 4,486 件の料金所のうち `payment:*` が付いているのは
  6.7% で、`payment:cash=no` は全国で 1 件。現金可否の判定には使えない。
- **NEXCO 東日本の「迂回先料金所」表**: ページ内に存在するが HTML コメントで無効化されており、
  公開を取り下げた内容と判断して使っていない。迂回先は距離から自前で求める。

### 判定できる範囲

NEXCO 3 社が一覧を公開している路線 (高速道路ナンバリングの E 番号、C3 外環道、C4 圏央道、
C2 名二環) だけを判定対象とする。首都高速・阪神高速・名古屋高速などの都市高速は
各社が別々に運用しており一覧が無いため、**現金可否を判断できない**。
これらは地図上で灰色にし、経路の候補には使わない。経路の途中で通ってしまう場合は警告を出す。

無料区間 (料金所そのものが無い) は常に現金で通れるものとして扱う。ただし
「本線データに見つからない」ことは無料の根拠にならないので、その場合は判定対象外とする。

スマート IC は制度上すべて ETC 専用なので、名称から機械的に ETC 専用として扱う。

## 使い方

```bash
npm install
python3 -m venv .venv && ./.venv/bin/pip install -r scripts/requirements.txt
```

データを取得して統合する (初回とデータ更新時):

```bash
./.venv/bin/python scripts/fetch_osm.py --refresh && ./.venv/bin/python scripts/build_dataset.py --refresh
```

開発サーバー:

```bash
npm run dev
```

## テスト

パース処理 (元データの表記ゆれに対する耐性):

```bash
./.venv/bin/python scripts/test_parsing.py
```

経路計画 (実際に Valhalla を叩くのでネットワークが必要):

```bash
node scripts/test_plan.mjs
```

`test_plan.mjs` は「選ばれた入口 IC が本当に現金で入れるか」「出口 IC が現金で出られるか」を
毎回検証する。ここが崩れるとアプリの意味がなくなるので、データ更新のたびに実行する。

## 公開

GitHub Pages に自動公開される。

- `.github/workflows/deploy.yml` — `main` への push でビルドして公開
- `.github/workflows/update-data.yml` — 毎週データを取り直し、件数の妥当性を確認してからコミット

件数チェックを入れているのは、取得元のページ構造が変わってパースが空振りしたときに、
壊れたデータをそのまま公開しないため。

## 制限と注意

- 料金所の運用は頻繁に変わる。**最終確認は現地の表示と各社の公式情報で行うこと。**
- 都市高速は判定対象外 (上記)。
- 所要時間は目安。渋滞や時間帯は考慮していない。
- 料金の計算は行わない。
- IC の位置は本線上の分岐点なので、地図上の点は料金所の位置と数百 m ずれることがある。

誤って ETC 専用レーンに入った場合は、停車して係員の指示に従うこと。後退は危険。
